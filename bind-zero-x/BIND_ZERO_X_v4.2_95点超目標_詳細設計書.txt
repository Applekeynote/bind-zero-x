2.1 目標を成果レベルで固定
  S0 正しい数学＋合成画像回帰、S1 OpenCV5実画像GT、S2 原因で選択行動が変化、

  S4達成なしで「人間より良い」禁止。S5達成なしで「崩れ・ほどけ・運びやすさ全改善」禁止。

2.2 製品利用者と実験対象
  家庭/小規模事務所、3〜10枚、既知の紙ひも、自治体規則を確認した軽量段ボール。
  日常モードは固定治具の利用を要求しない。研究モードではマーカー/治具/荷重計/固定カメラを使う。
  研究モードの実測値を、装置不要の一般利用へ転用する場合は別の検証が必須。

2.3 研究の中核仮説
  H-M：CAPE能動試験は同じ費用・安全制約の固定試験より誤った修正率を低下させる。
  H-U：CAPEを用いた全仕事は熟練者が選ぶ現実的な方法より実用利益がある。
  H-Q：共通負荷試験で少なくとも1つの故障の相対変位が計測可能である。
  H-C：各要件（滑り、結び目、運搬）を異なるアウトカムで示せる。
  H-S：簡単な束では何もしない・不確実なら保留という選択で過剰介入を抑える。

2.4 成果の非目標
  ひもの安全耐荷重保証・高荷重引張・吊り運搬・転倒/人体への落下試験・一般材質の摩擦推定・
  未確認の自治体回収規則の断定・世界初/特許非侵害の保証・2026以降の汎用ロボット実装。

03. 対象利用者・需要・ジョブ評価
========================================================================================
3.1 課題仮説
  家庭での結束失敗は頻繁とは限らない。繰り返し失敗・不揃い・運搬距離が長い場面を優先。
  『使いたい』という口頭回答は利用証拠にならない。必ず操作の負担を測る。
  競合は十字縛り、適切な分割、結束補助具、段ボールストッカー、情報サイトである。

3.2 インタビュー：10-20名（探索的、代表調査ではない）
  質問：過去3か月での回収回数・失敗回数・失敗の内容・普段の方法・
        平均所要時間・再結束の有無・分割判断・カメラ設置環境・操作許容時間。
  避ける質問：『この素晴らしいAIを使いたいですか』等の誘導。
  作業観察：少なくとも3名の現状法と2名のアプリ操作を記録（同意必須）。
  「何も困っていない」回答もそのまま残す。

3.3 価値の計算
  T_job=T_prepare+T_scan+T_plan+T_tie+T_probe+T_rework+T_carry+T_cleanup。
  失敗率差による時間便益: (p_baseline-p_AI)*T_retry - T_app_extra > 0 が目安。
  これは近似であり、負担・道具価格・故障時の損失も別途評価する。
  追加時間の中央値が通常法より長い場合『時短』は主張不可。

3.4 ユーザーに見せる最小価値
  普通の束：『現在の観測で追加介入は不要。標準方法を参照してください』。
  不揃い：『第n層が大きく突出、再配置候補を提案。効果は未検証』。
  結束後：『低負荷試験で第n層の残留相対変位を測定。結び目強度は未測定』。
  隠れ：『横から再撮影が必要。見えない部分の安全は判断できない』。

05. 全体アーキテクチャ・責務分離
========================================================================================
5.1 データフロー
  Smartphone Browser (React) --HTTPS--> FastAPI AWS EC2
    -> Upload validation -> S3 presigned private assets
    -> OpenCV 5 Worker (校正、検出、追跡、計測、品質判定)
    -> Safety/Rule Engine (制約・禁止行動・回収方式・中止)
    -> CAPE-4.1 Deterministic Core (候補・観測仮説・試験価値・再計画)
    -> Bedrock Bounded Agent (候補内の選択提案と説明; 規則違反時棄却)
    -> DynamoDB (状態/イベント/version/probe_count)
    -> Browser (可視化、本人の承認/実施結果入力)
    -> 再動画 -> 同じCV Worker -> 最終チャレンジ/ログ/集計
    -> CloudWatch (生画像を含めないメタデータ)

5.2 責任境界
  OpenCV：何がどれだけ見え・移動したかを測る。強度・張力は捏造しない。
  CAPE：どの行動が改善を見込めるか、どの追加観測に価値があるかを計算。
  Bedrock：allowlistの範囲で候補を提案・説明。唯一の正解・安全の権威ではない。
  Validator：モデルに優先する強制制約。人間に無理をさせない。
  Human：物理操作の実施者。実施完了を明示的に報告。拒否・中止権あり。
  Evaluation：すべての群に共通の標準チャレンジで成功を判定。

5.3 モード
  FAST：撮影→大きな問題が観測されなければ標準法→終了。安全保証ではない。
  ASSIST：撮影→候補→人が結ぶ→低リスク追加試験が有益なら実施。
  RESEARCH：標準治具、固定カメラ、校正、別のGT、厳密ログ、人工故障を利用。
  家庭向けモードの性能を、研究用治具ありの数値で代用しない。

  計測器の分解能・誤差・校正日をInventoryへ登録し、不明ならその値をGTに使わない。

6.3 外部環境の記録
  照明、撮影距離、画角、床材、カメラ高さ、試験方向、束の質量、室内湿度を記録。
  ひもロットが変われば同一条件扱いしない。材料損耗のある再試験は別trialとする。

6.4 安全
  低い台、軽量の試料、防護、力の上限事前決定、実験者の停止操作。
  試験荷重の絶対値は本書で断定せず、材質・治具の限界をパイロットで確かめた後、
  設計責任者が試験開始前にF_maxを記録する。無制限な力や衝撃は禁止。
  吊り持ち・人の足元に落とす・高所・車両固定は対象外。

07. 可観測性と物理実験成立性
========================================================================================
7.1 可観測性と原因の同定不能条件
  上面・側面の2Dカメラでは視線方向移動、隠れたひも経路、内部結び目の構造は基本的に不明。
  カメラが動く場合は背景マーカーからカメラ変換G(t)を独立推定。物体の複数平面へ
  一枚のホモグラフィでmm計算を行わず、各層/視点で校正可能な範囲を厳守。
  層iの剛体位置をT_i(t)∈SE(2)、jの位置をT_j(t)とすると相対位置R_ji=T_j^-1 T_i。
  すべてに共通な任意のSE(2)運動W(t)について(WT_j)^-1(WT_i)=T_j^-1T_i。
  これが満たせない推定/数式は採用しない。

7.2 摩擦・滑りの実験成立性
  揺動x=A sin(2πft) → amax=(2πf)^2A。5mm・1Hzは約0.020gで、実際に滑らない可能性が高い。
  高振幅へ安易に変更せず、軽量の準静的試験片・独立荷重計・低位置ガードを用いる。
  まず【既知の相対移動を観測できる】こと、次に【安全な入力によって区別可能な故障が生じる】
  ことを別々に検証する。装置の故障発生率と、本来の回収中の故障発生率を混同しない。

7.3 研究モードで必須の独立GT
  層間運動：デジタルノギス/変位治具/追加カメラのうち誤差が把握されたもの。
  試験負荷：校正済みの荷重計/ロードセル、試験時間は独立時計/フレーム時刻。
  ひも：結び目端部とひも本体の別々の材料点。
  分割時：元枚数・全束搬出・往復数・総ひも長。GTの誤差自体も報告する。

7.4 止める条件
  independent GT not available→『正確なmm』を表示せずピクセル/不確実性のみ。
  面外移動/マーカー脱落/遮蔽/未知スケール→UNKNOWN。ゼロ変位扱い禁止。

08. OpenCV画像実験と計測パイプライン
========================================================================================
8.1 実画像アルゴリズム（開発ターゲット：OpenCV 5）
  (1) 動画デコードと回転メタデータ整合、解像度・fps・長さの上限。
  (2) カメラ内部パラメータと平面ごとのmm換算を確立。背景マーカーでカメラ移動を独立追跡。
  (3) 各層ROI/材料固定の特徴点抽出 cv2.goodFeaturesToTrack。
  (4) calcOpticalFlowPyrLK の双方向追跡、forward-backward誤差・欠測を記録。
  (5) 各層ごとestimateAffinePartial2D+RANSAC、inlier個数と残差P90を記録。
  (6) 類似変換の推定値にスケールが含まれる→スケール逸脱を棄却してSE(2)へ投影。
  (7) 剛体回転Rを推定したあと、t=median(q1−R*q0)で平行移動を再推定。
  (8) 世界座標・カメラ座標・初期材料点座標を明示し、相対運動のみ比較。
  (9) 層i-jの相対変換、可視アンカー変位、相対回転、変形残差を別々に出力。
  (10) 結び目/ひもは別観測。計測品質が不十分ならreason付きnull。

8.2 合成画像の検証を実装
  code/test_synthetic_opencv.py：2種類の独立層模様を生成し、既知の剛体運動と相対滑りを加える。
  10シナリオ：全体並進、全体回転、並進+回転、5px滑り、全体運動+5px、10px、相対回転、
  遮蔽、スケール逸脱、特徴なし。閾値はコード中固定。実行seed固定。
  実行結果：OpenCV 4.13.0に限り10/10 PASS（2026-10-12）。これは物理GTではない。
  OpenCV5へのコード移植ゲート：EC2上で実行版/ビルドを記録、同じ10ケースを再実行。
  OpenCV 5で10/10 passしても物理的な層の識別成功ではない。

8.3 リアルカメラの条件別校正
  既知0/2/5/10mm×X/Y方向×撮影距離3×照明2×反復3以上。
  シナリオを設定した後、パイロットでGT分解能・ノイズを確認して閾値を凍結する。
  MAE<=1mm/P95<=2mmは研究モード挑戦目標。未達時は適用範囲制限又は計測不能扱い。
  可視ケースの精度と、棄却を含む全ケースの判定可能率を並記。
  内部測定区間の95%被覆は、独立したデータで実測カバレッジを確認するまで『95%CI』と呼ばない。

8.4 動的評価の失敗を防ぐ
  残留変位は十分静止した区間の平均姿勢から算出。
  追跡点が剥離/層間入替した場合は前後値を継続して使わずINVALID_ID。
  非剛体変形はRANSAC残差・輪郭形状変化で別途分類。面外成分は無条件で0mmにしない。

09. SE(2)相対変換と数学・画像検算
========================================================================================
9.1 採用する幾何モデル
  初期材料座標系が固定された層iについて、共通座標への変換をT_i(t)∈SE(2)とする。
  iをjから見た相対姿勢：R_ji(t)=T_j(t)^(-1)T_i(t)。
  相対変化：ΔR_ji(t)=R_ji(0)^(-1)R_ji(t)。
  これは共通左作用W(t)に不変。ただし初期材料座標系/回転中心の選択に注意する。
  固定アンカーa_i（初期に決めた材料点）について、
    d_ij(t;a_i)=||R_ji(t)*a_i - R_ji(0)*a_i||。
  D_dyn=max_{(i,j)接触対,a,t} d_ij(t;a)、D_res=終了静止区間の同量の最大。
  θ_ij=wrap(angle[R_ji(t)]−angle[R_ji(0)])。
  剛体近似が大きな残差を出す場合はNONRIGID、無視してslide_mmを確定しない。

9.2 よくあるバグと対策
  旧『2点間距離の差』→同距離の横移動を見逃す。旧『相対ベクトル変化』→共通回転で偽滑り。
  単純な2x3行列からスケール混入を無視して剛体に見せることも危険。
  Raw affinityからscale=sqrt(a²+c²)を計算。|scale−1|>pilot固定閾値なら棄却。
  射影後、対応点の残差を再計算。小さくなければHIGH_REPROJECTION_ERROR。
  同一物体でも完全な剛体とは限らないため、ローカル変形とglobal motionを明確に分離する。

9.3 コード検証範囲
  test_se2_math.py：数学13件、現行のpython stdlib環境で再実行。
  test_synthetic_opencv.py：LK光フロー、RANSAC、SE2射影後の実画像配列テスト10件。
  いずれも合成/理想入力であり、GTと同じ算式で正解を作る循環的検証を避けるため、
  実物校正GTはノギス等で独立取得する。

9.4 判定区分
  MEASURED_CONFIDENT：校正済み、実測誤差が閾値に対し十分小さい。
  UNCERTAIN_SLIP：誤差帯が滑り判定閾値と重なる。
  OUT_OF_SCOPE：マーカー不可、面外運動大、材質外、層ID不正。
  RECAPTURE：画角/光量/遮蔽の改善で再計測可能な状態。
  値はvalue_mm nullable、unit、reference_frame、quality、scope、estimate_methodを伴う。

10. ひも・結び目の独立診断
========================================================================================
10.1 診断対象の分離
  LAYER_SLIP/RELATIVE_ROTATION：隣接層の相対剛体変換。
  ROPE_PATH_SLIP：段ボールの材料点に対するひも経路基準点の移動。
  KNOT_SLIP：結び目本体に対するひも端部の相対移動。
  LOCAL_DEFORMATION：剛体モデルが説明できない形状変化。
  これらは独立しないので多ラベル。一つしか見えない時も他原因はUNKNOWNのまま。

10.2 識別と判定保留の別評価（F31-02）
  Coverage = 非保留の件数 / 全件数。
  Selective accuracy = 非保留かつ正しい件数 / 非保留の件数。
  非保留0件ならSelective accuracy=null、Coverage=0で性能仮説不支持。
  故障カテゴリ別のPrecision/Recallを、保留を負例に置換せず、全試行分母を明示して計算。
  GTが原因=positiveでもUNKNOWNなら原因識別のRecallにおいて見逃しとして算入。
  可視性不足による正当な保留はSafety/Abstention試験では合格になり得るが、
  Cause-identification性能実証では合格に数えない。

10.3 性能ゲート（パイロット後に固定する挑戦値）
  独立holdoutの可視な模擬原因3種それぞれ原則12件以上を確保。
  事前目標: coverage>=0.80、Precision>=0.85、Recall>=0.85。
  個別12件では閾値付近の統計的不確実性が大きいので、目標達成だけで一般化保証しない。
  GT不足、クラスが偏る、判断保留のみの場合はNOT_SUPPORTEDまたはINCONCLUSIVE。
  PHYS-012/013/014とPHYS-025で原因別指標を同時評価。

10.4 解けにくさの追加試験
  Knot基部の材料マーカー・ひも端部マーカー・荷重計の3つを独立に記録。
  負荷は承認済みの小荷重規格を採用し、保持秒数/反復/材料ロットを固定する。
  K_resとunravel件数、ひも全体移動K_pathを別列で保存。
  結び目改善の主張は対照法との実測比較に基づく。層間滑りの改善では代用不可。

11. 安全な試験と段階ゲート
========================================================================================
11.1 先行ゲートの順序
  G0-A 純粋SE2数学13件→PASS済（ローカル）。
  G0-B synthetic image OpenCV10件→PASS済（cv2=4.13に限定）。
  G0-C OpenCV5上の同10件→NOT_RUN。大会に必須。
  G1-A 独立GT付き実カメラ0/2/5/10mm→NOT_RUN。
  G1-B rope/layer/knot故障を独立ラベルで同定→NOT_RUN。
  G1-C 標準試験Qの安全・再現性（入力と試験片応答を分離）→NOT_RUN。

11.2 物理試験は低荷重・低位置で実施
  事前のリスク点検/Fmax承認/保護ガード/作業員同意/中止操作を満たさない場合はBLOCKED。
  見栄えのために負荷を強めたり、紐を握って吊り上げたりする試験を禁止。
  結束ルールと安全荷重は別。視覚だけで張力・強度を推定したと述べない。

11.3 各故障モードの識別不能を含む計測
  LAYER_ONLY: 層の既知移動、ひも静止。ROPE_ONLY: ひも経路の移動、層は静止。
  KNOT_ONLY: 結び目端部のみ既知滑り、束形状変化なし。
  MULTIPLE: 層とひもが同時移動。NEGATIVE: どこも滑らない。OCCLUDED: 不明。
  各試行はGT・動画hash・荷重波形・照明・撮影距離・材料ロット・ラベルの根拠を保存。
  致命的な悪化・破断兆候→ABORTED、分母に残す。

11.4 成立を判定する2本立て
  (a) 検証手順合格：試験条件・測定・安全の管理が正しかったか。
  (b) 故障識別実力：カバレッジ、モード別recall/precision、誤確定率が目標を満たしたか。
  3モードの人工故障では暫定coverage≥0.80かつ各Recall/Precision≥0.85を探索目標。
  希少原因・未知画角では達成を未保証とし、自然事象での外挿は別試験。

11.5 Pilot後の事前凍結
  応答がほぼ0mmとなる弱振動は無理に成功とせず『物理刺激として無効』と記録。
  振幅,周波数,荷重,持続,繰返し数,測定分解能,stop condition,質量上限を固定。
  運動プロファイルを変えたら新たなchallenge_idを作成し過去の結果と混ぜない。

========================================================================================
12. 標準チャレンジ試験と交絡制御
========================================================================================
12.1 評価基準チャレンジQの分離
  P=診断試験（AIが提案・選択する）。Q=全比較法の最終性能を測る共通入力。
  Pで起きる物理状態変化は後続Qへ影響するため、介入前後を独立に記録。
  Pの回数・時間・累積荷重・材料の緩みをE/Dで記録、可能なら負荷マッチ補助群を設ける。

12.2 Qが『同じ』である意味
  同じchallenge_idであるだけでは不足。fixture_revision、mass_g、material_batch、
  amplitude_actual、frequency_actual、acceleration_actual、force_actual、duration_actual、
  camera_view、environment、operatorなど主要条件を記録。
  パイロット後に数値公差を事前登録し、Qの実測入力が公差外なら逸脱にする。
  二束化の各束にも同じQ仕様を適用し、全枚数に対するworst-case結果を取る。
  目的が異なるQ_knotとQ_bundleの入力を混同しない。

12.3 試験順序と交絡
  既にD群で荷重試験した束をE群に流用しない。独立試料へ割当可能なら優先。
  避けられない場合、順序効果・材料摩耗・プローブでの初期損傷/なじみを記録し、
  因果的優位は保留。被験者の慣れにも順序無作為化またはバランス化で対処する。
  人間対照Bには自然な再配置/分割を許す。Aのひも結び技能を故意に制限しない。

12.4 Qの合否
  プロトコル適合PASSは、全armが規定入力・独立GT・許容差・履歴要件を満たすこと。
  効果仮説SUPPORTEDは、上記PASSとは別に、実測物理結果と比較の不確実性に基づく。
  Qをきれいに実行できたがE=Bなら『試験実施成功・改善未確認』が正しい。

13. 状態推定・原因ラベル・確率モデル
========================================================================================
13.1 原因の多ラベル状態
  M=[LAYER_SLIP,ROPE_PATH_SLIP,KNOT_SLIP,RELATIVE_ROTATION,
     LOCAL_DEFORMATION,EXCESSIVE_CARRY_BURDEN]。
  UNKNOWNは独立した可視品質/未同定フラグであり、他原因と排他的な真の故障種ではない。
  複合故障は[M1=true,M2=true...]と記録し、softmaxで無理に単一ラベル化しない。

13.2 MVPの原因決定表
  (i) 信頼できるH_jiの相対並進だけ明瞭 → LAYER_SLIP候補。
  (ii) 相対角のみ大きく並進小 → RELATIVE_ROTATION候補。
  (iii) ロープ基準点が層材料点に対して移動 → ROPE_PATH_SLIP候補。
  (iv) 結び目端部が結び目基部に対して移動 → KNOT_SLIP候補。
  (v) 複数確認 → MULTIPLE。
  (vi) GT可視性不足/校正無効/閾値区間跨ぎ → UNKNOWNまたはRECAPTURE。
  この決定表は物理原因の真実を保証しない。必ず人工GTで正答率を測る。

13.3 確率と情報価値の限界
  有効な独立データが十分でなければp(y|M,a)を推定したと主張しない。
  初期MVPは明示ルールと観測品質で行動を選び、実験により確認する。
  ベイズ/EVSIは独立holdoutで校正が成立した場合の拡張機能。Brier/Calibrationを報告。
  95%のLLM確信度を95%安全や95%故障検出率として扱わない。

========================================================================================
14. CAPE-4 行動価値・許容行動集合と評価
========================================================================================
14.1 成果志向のCAPE-4（CAPE-3の後継実装方針）
  CAPE-4 = Counterfactual Active Probing & Editing, action-value constrained.
  重要：アルゴリズムの名称や期待情報利得の式そのものは独創性の証明にならない。
  設計上の核は「試験しない」「固定試験」「低リスク追加視点」「許可された物理試験」から、
  合理的な費用で最終行動の質を上げる方策を選ぶこと。

14.2 費用・結果の単位整合
  修正行動u、潜在故障状態m、観測y、診断a、前情報bを定義。
  直接修正リスク R0=min_u E[L(u,m)|b]。
  診断で物理状態が変わらない近似下では、R_a=C(a)+E_y[min_u E[L(u,m)|b,a,y]]。
  診断が束の状態を変える場合はp(m_next,y|m,a)で状態遷移を考慮。
  R_a=C(a)+E_{m_next,y}[min_u E[L(u,m_next)|b,a,y]]。
  事前に共通の金銭換算・時間換算・無次元化等の効用定義がない限りEIGを秒と直加算しない。
  実モデル未取得のMVPではこれを『数理目標』に留め、ルール型の試験選択へフォールバック。

14.3 一意な正解行動に依存しない評価
  結束には複数の合理的解（再配置・二束化など）が存在する。
  各試料xで許容修正集合 U_acc(x)={u:L(u,x)≤L*_x+ε} を構成。
  regret(x)=L(u_AI,x)-min_u L(u,x)（同じxの複数行動が独立実測できた場合のみ）。
  物理的に未観測の反事実についてregretが既知であると捏造しない。
  初期の判定は、部分観測でも明らかに悪いactionと合理的に許容されるactionを段階付けし、
  許容集合が同定できない場合はACTION_ORACLE_UNDETERMINEDとする。

14.4 観測→行動の因果Trace
  [video_hash]→[opencv5 metrics+quality]→[candidate actions]→[probe/no-probe ID]→[human approval]
  →[followup_video]→[changed failure hypothesis]→[new action ID]→[measured Q outcome]。
  同じ初回画像から異なる診断後観測で別の行動が選ばれることを、実現したログで示す。
  ルール型・固定型・推定EVSI型の結果を混ぜず記録。

14.5 Bedrock役割
  Bedrockに許可された理由説明/候補選択を行わせるが、世界の強度や安全の唯一の権威にはしない。
  CV数値・許可集合・人間承認・力学試験の上限は決定論的コード側で検証。
  API異常/幻覚/未知actionの場合、安全な手動法へ戻る。Bedrockなしの比較も行う。

14.6 優位性評価
  VAL-M01 E-D誤修正率、VAL-M02同等のcoverageでの試験費用/回数、
  VAL-M03/04許容行動集合/物理regretと予測を照合。valの合格条件はPilot後に凍結。
  E-Dの性能差を示せない場合、独創性向上が証明されたと宣伝しない。

========================================================================================
15. 物理再配置・束分割・結束候補
========================================================================================
15.1 MVP候補を小さく固定
  KEEP、幅広板を下に置く、端の突出を減らす、合法な方法で結び直し、
  合法なひも経路の位置調整、最大2束に分割、観測不能→保留。

15.2 計画器
  全順列を探索しない。上位5候補のbeam searchまたは明示ルール。
  事前画像の幾何スコアG=uncovered_area+edge_offset+rope_asymmetry+unknown_penalty
  の標準化重みを事前固定。実測残留滑りとの相関がなければ候補順位に使わない。
  質量は画像から捏造しない。ユーザーのはかり値またはUNKNOWN。

15.3 対照方式の定義
  A: 標準十字縛り（正しく訓練された作業者）。
  B: 経験者が自由に並べ直し・分割・適切な既存結束方法を選択。
  C: CVの初回画像だけで候補選択、追加診断なし。
  D: 固定された診断試験→原因推定→再計画。
  E: CAPE-3能動選択→原因推定→再計画。
  全群とも違法な材料・方法は禁止。A/Bでも同じ運搬条件と安全制約。

15.4 分割の公平な計算
  N枚を全て搬出する『1仕事』を単位とする。
  二束化なら片方の束だけの低い変位を成果にしない。
  最大変位=両束の最悪値、時間=準備+全束の移動+戻りを含む、ひも=全束合計。
  同じ数量を運び終えるまでに使う総仕事量も示す。

16. AWS/OpenCV5必須構成と状態管理
========================================================================================
16.1 必須AWS構成（実働確認までは設計）
  React/Vite→HTTPS→FastAPI on AWS EC2→OpenCV5 CV worker→CAPE4 rules→Bedrock bounded choice
  →DynamoDB session/event & S3 private media→CloudWatch structured telemetry。
  EC2はx86優先、Graviton/COOLは互換性の証拠を得てから。実行環境のDocker digestを保存する。

16.2 公式必須のRuntime Gate
  CLOUD-001/META-001/CV-025：AWS実行環境でcv2.__version__ major 5（ビルド含む）。
  META-002：匿名化した実動画をAWSでOpenCV5解析→安全な次行動→人間承認→新動画→監査ログまで1回完走。
  ローカルOpenCV4での合成検算はこのゲートを満たさない。
  model access, structured output対応, Bedrock region は実環境で再検証し、動かないなら明記。

16.3 永続状態
  session_id, owner_sub, state_version, probe_count, recapture_count, current_state,
  last_observation_id, selected_action_id, approved_action_id, last_probe_id, policy_version, rule_version。
  event書込みには条件付き更新/トランザクション/冪等性キーを使用。
  probe_countは実施確定の一回のみ増分。タイムアウト時の再実行で二重増分しない。
  PENDING approval→ユーザーが実作業→execution confirmation→新観測の順番を強制。

16.4 テレメトリ
  request_id, CV runtime version, instance architecture, video SHA, frame_count, per-layer quality,
  measured motion, action code, human approval, server latency, bedrock token use, cost estimate。
  CloudWatchにはraw PIIや生動画を記録しない。S3 presigned URLは短期限、bucketは非公開。

16.5 障害時
  OpenCV解像度超過→明確なUPLOAD_REJECT/RECOVER、カメラマーカーなし→RECAPTURE、
  Bedrock拒否/timeout→定めた通常法/ABSTAIN、DynamoDB 409→reload、試験中止→ABORTED。
  5xxや古いversionの際に物理操作を完了扱いしない。

17. Bedrockの境界とAgentic Vision証拠
========================================================================================
17.1 Bedrockの位置付け
  CVの観測値、許可済みの次の行動、既存の制約だけを受ける。
  ユーザーの目の前の実測値・安全荷重・自治体規則を創作しない。
  候補選択の理由を構造化し、人間が操作前に承認できるUIを提供する。
  LLMの出力はschema検査、action allowlist、数値出典検査、現在state検査を通す。

17.2 条件付きの価値比較
  同じholdoutでRULE_ONLY、BEDROCK_BOUNDEDを比較する。
  不適切行動率、未観測時の保留率、追加処理時間、説明の理解度を比較し、
  Bedrockの付加価値が明らかでなければ単に文章生成の補助と説明する。

17.3 Agentic Vision受入
  実物OpenCV 5観測の違いがaction_code/probe_codeを変え、
  人間承認を経て別の結果動画が計測される完全トレースが必要。
  同じ初回画像＋異なる実測プローブ観測で3つの行動を出す試験は、
  GT行動の混同行列と組み合わせて評価する（単に文字列が異なるだけでは不可）。
  prompt injection、架空数値、無許可行動、Bedrockタイムアウトはすべて拒否/保留。

18. セキュリティ・プライバシー・費用
========================================================================================
18.1 入力
  presigned URLの権限・有効期限・アップロード先prefix制約。
  許可するmime/codec/動画長/容量/最大画素数/フレーム数をサーバーで実際に検証。
  Content-Typeだけで許可しない。zip bomb的な圧縮画像・悪意あるcodec・パスを拒否。
  処理timeout/メモリlimit、ローカル一時ファイル自動削除、アップロード成功時だけ状態更新。

18.2 権限
  HTTPS/TLS。CORSは限定origin、認可の代替として使わない。
  JWTのissuer/audience/expiryを検証。owner_subで全セッションを認可。
  公開トレースは匿名化・許可制。生映像URLは長期公開しない。
  EC2 roleで最小権限、IAM secretsをコード/動画/ログへ埋めない。

18.3 保存
  同意前の生動画保持なし。EXIF/位置情報削除、顔・住所情報は可能な限り入力時トリム。
  S3 Block Public Access、短期lifecycle、明示削除API、メタデータTTL。
  ただしDynamoDB TTLとS3 Lifecycleは即時削除保証ではない。削除要求では直接Deleteも実施。
  監査用の匿名化メタデータの保持可否は別同意。

18.4 Bedrockログ
  Bedrockモデル呼出ログはデフォルト無効。明示有効にすると入力/出力が記録され得る。
  モデルへ原動画全量を送らずCVで抽出した指標を渡す。
  自前の安全なstructured telemetryのみCloudWatchへ保存、顔・住所・生画像は記録しない。

18.5 料金
  EC2稼働時給、Bedrock per request/tokens、S3 storage/requests、DynamoDB、
  ネットワーク転送、CloudWatch ingestion を毎日記録。AWS Budgetsは通知であり課金遮断保証なし。
  max_sessions/day、max_video_sec、timeout、EC2停止手順で自律的な制限を実装。

20. 3要件の独立アウトカムと結果の二層表示
========================================================================================
20.1 3要件は最初から独立計測
  A 崩れにくさ：共通チャレンジQ後の元全束における最大層間D_res(mm)、抜け落ち率。
  B 解けにくさ：規定低荷重結び目の端部K_res(mm)、ほどけ件数。ひも経路移動とは別。
  C 運びやすさ：元N枚の準備→撮影→AI待ち→結束→修正→運搬→戻り→片付けT_job(sec)。
  分割の際はすべての束と全枚数を含め、運搬回数・紐長・負担を合算する。
  どの指標も構成ごとのpaired difference、ばらつき、未測定・中止を併記する。

20.2 提出する結論の二層表示
  PROTOCOL_STATUS: PASS/FAIL/BLOCKED/NOT_RUN/INCONCLUSIVE。
  EVIDENCE_STATUS: SUPPORTS_IMPROVEMENT / SUPPORTS_WORSE / NOT_SUPPORTED / INCONCLUSIVE / NOT_EVALUATED。
  例えば同条件の実験が正しく完了しても差が0ならPROTOCOL_PASSとEVIDENCE_NOT_SUPPORTED。
  『非劣』は事前の非劣性マージン・信頼区間を要する。単なる差が小さいは非劣とは呼ばない。

20.3 条件付き開発目標（実測値ではない）
  A 対標準法の残留相対移動30%減は仮目標。B=熟練者には実際のデータに基づく比較。
  B 結び目保持力の改善は独立データがあるときのみ主張。
  C 総作業時間が増えたら「時短」を絶対に主張しない。
  E-Dの情報価値は単純原因分類だけでなく、修正の質・試験回数・負担で検証。
  改善幅の最低実用差δはパイロット終了後/holdout解析前に明示的に決定し凍結。

20.4 失敗/中止・途中未完了
  未完了仕事は完了時間が欠損する。これを0として処理しない。
  主要分析は仕事の失敗件数・完了率を先に示し、完了した場合の時間を別報告。
  非完了を消したper-protocol解析だけで時間改善とは主張しない。
  事前登録の複合エンドポイントや感度分析で失敗の不利益を評価する。

21. 比較実験・事前登録・統計
========================================================================================
21.1 比較群（変更しない）
  A 適切に行う標準十字縛り、B 熟練者が自由に再配置/二束化、C 初回画像のみ、
  D 固定試験＋再計画、E CAPE-4能動試験＋再計画。
  Bに不利な人工制限を課さない。すべて同じ合法ひも・元枚数・Q・品質基準。

21.2 2系統の主要な仮説を分離
  M-TRACK：制御された故障＋独立GT、E-Dで誤修正率/原因識別/診断負担を検証。
  U-TRACK：現実的な不揃い束、E-Bで全枚数搬出の失敗率・総時間・滑り・結び目を検証。
  誤修正の正解が複数の場合は許容行動集合。独立実物で観測できない反事実は未評価。

21.3 事前登録用の結果定義
  M主アウトカム：全評価ケースを分母とする誤った確定修正率、保留率も別掲。
  U主アウトカム：全枚数の仕事完了/中止を含めたT_job。作業失敗数を先に提示。
  副次：層残留変位D_res、結び目K_res/ほどけ、作業回数、ひも量、主観負担。
  主要対比を後で変更しない。改善目標δ_M,δ_Uなどはpilot→freeze→holdoutの順序で決める。
  試験数を元に統計的有意性や検出力を断定しない。標本数とパワーを実測ばらつきから計算。

21.4 実験計画の現実的な優先順位
  Pilot：6構成×初期3方法=18試行を品質確認に利用し主結果に混ぜない。
  MVP holdout優先：M-TRACK 異なる故障ケースを12以上の独立構成で調べ、E-Dを比較。
  U-TRACK 8構成×B/E=16仕事＋A/Cが可能なら追加。少数の探索実験と明記。
  時間に余裕なら8構成×5群=40、望ましくは別物理セットで反復、未見試料へ拡大。
  いずれも試験を少なくしたら広いCIと探索的な結果を適用範囲付きで示す。

21.5 効果推定と独立性
  paired differenceをconfig単位で計算。構成内の反復動画は独立の新問題に数えない。
  小n時は独立構成の符号/順位と効果幅/不確実性を主に示す。CIが広い場合はINCONCLUSIVE。
  欠測・中止は事前ルールで扱う。束分割の部分搬出をcompletedにしない。
  入力物理波形の実測差がQの公差を超えたら不一致扱いにする。

21.6 交絡と順序管理
  ひも摩耗/繰返し/作業者の練習/プローブ自体による緩みをそれぞれ記録。
  DとEの診断試験回数・総試験時間・入力負荷を比較可能にする。
  同じ物理束でD→Eを続けた結果を独立比較とはみなさない。可能なら同仕様の別試料。
  物理入力が一致せず比較不能でもその事実をレポートに残す。

21.7 実施前に埋める必須ファイル
  v4_事前登録テンプレート.json（status TEMPLATE_NOT_REGISTERED）。
  値がnullの荷重限界/効果幅/許容差/試験の停止条件を決定したらv4.0-frozen版を別保存しSHA取得。
  凍結前の設計目標を『既に前登録した』と表現しない。

22.1 データの出自を混同しない

22.4 GTの循環参照禁止
  OpenCVの推定点を正解値として使わない。別の独立治具／ノギス／別視点をGTとして採集。

22.5 回転と面外の対照
  全体一体回転・全体並進・対象層のみ回転・対象層のみ滑り・複合滑り・遮蔽を含める。
  OpenCV4ローカルsynthetic10件は準備検算。OpenCV5と実画像の同じ失敗モードを必ず追加。

23. 235件テスト台帳・実行分類・主張の境界
========================================================================================
23.1 合否を分離する
  TEST_STATUS = NOT_RUN/IN_PROGRESS/PASS/FAIL/BLOCKED/INCONCLUSIVE/N_A。
  PERFORMANCE_HYPOTHESIS = NOT_EVALUATED/SUPPORTED/NOT_SUPPORTED/INCONCLUSIVE。
  あるテストの試験プロトコルPASSは、AIが従来法より有効であることを意味しない。

23.2 v4台帳
  v3.1旧196件は削除せず保持。SCV10件、VAL12件、META5件、RULE12件を追加して計235件。
  重要：合成CV4はコード上通過していても、OpenCV5物理実証の必須要件を満たさない。
  台帳235件はすべてNOT_RUNとし、ローカル47個の純粋/合成検証は別の実行ログへ記載。
  要求数：旧51個＋13個の新評価/必須仕様＝64要求。
  要求追跡：PRIMARY1つに加え、SECONDARYの複数関連要求を紐付けた多対多形式。

23.3 テストの実施担当の区分
  AUTO：unit、stats、schema、同条件画像フィクスチャ。
  SEMI_AUTO：物理試験の安全な実行後、機械的に計測/集計。
  MANUAL：実験者が介入/被験者が操作/独立GT収集。
  REVIEW：実験登録・安全・Devpost提出の独立点検。
  分類から合格を推定しない。

23.4 カテゴリの優先度
  BLOCKER：大会必須OpenCV5/AWS、本質的な数式、セキュリティ/承認/安全停止。
  P0：現実の故障を1個以上識別し、観測により行動が変わること。
  P1：各分野の精度・統計・人間対照を掘り下げる。
  P2：特別賞や汎化拡張。低優先度のテストがPASSしてもBLOCKER不足を補えない。

23.5 効果に関する追加検証
  VAL-M01/M02：誤修正、固定試験との差、同じbudget。
  VAL-M03/M04：複数適切行動/反事実の出自。
  VAL-U01-U04：人間対照の総時間・層移動・結び目・身体負担。
  VAL-S01/S02：不介入と危険な誤確定を減らす。
  VAL-G01/G02：未見構成・低頻度故障での一般化。
  これらは計画であり現物比較は0件。

23.6 終了前のBLOCKER基準
  OpenCV5 in AWS実稼働、CV real GT、少なくとも1原因識別、観測→行動変化、人間承認、
  不確実なら保留、共通Q、プライバシー、クラウドログ、動画/再現性。
  重大FAILを『ほかのPASSの総数』で相殺しない。

24. 詳細実験・統計プロトコル
========================================================================================
24.1 CV測定試験
  独立GT：0/2/5/10mm×2方向×3距離×2照明×3反復。
  MAE,medianAE,P95AE,rejection rate, false positive, scale, reprojection error, GT uncertaintyを報告。
  3D/面外/滑るマーカー/追跡点入替はUNKNOWNかNONRIGID。

24.2 物理故障識別パイロット
  LAYER_ONLY/ROPE_ONLY/KNOT_ONLY/MULTIPLE/NORMAL/OCCLUDEDを校正済み治具で作成。
  刺激の荷重/速度/時間と前後状態を別々に記録する。
  まず単一故障を正確に観測できるか。その後自然に近い束で検証する。
  全件UNKNOWNでは性能条件不合格。機構の受入はcoverageと各モードprecision/recallの両方。

24.3 共通Qのフェアネス
  Qの文字列IDが一致するだけでは不十分。試料質量・材質・治具revision・実測入力の
  力N、振幅mm、周波数Hz、試験時間secが指定公差以内で一致する必要がある。
  code/evaluation_core.pyのvalidate_challengeを同等入力検査のベースに使用。
  実験前に公差を凍結、Q試験入力不足なら比較結果に採用しない。

24.4 実用評価
  元N枚をすべて運ぶ。同じ短距離・下支え・安全な低質量を使用。
  T_job = 材料準備+撮影+クラウド待機+作業+再作業+追加試験+全往復+片付け。
  未完了・中止は完了時間と別の失敗アウトカムで記録し、都合よく削除しない。
  報告は全仕事の完了率、完了時の時間、作業者負担、D_res、K_res、ひも長。

24.5 小標本の統計
  configuration単位のpaired Δで順位/範囲/CI/実用差を示す。多重比較の乱用を避ける。
  n=8は探索的。確証的な「85%以上確信」等は言えない。独立条件の不明確さがあれば明示。
  3アウトカムのうち1つが有意なだけで全要件達成とは表現しない。

24.6 行動Regretの実測
  物理状態の同一性を保持するため、独立試料/構成マッチ/ランダムな群配置で比較する。
  複数修正が許容されることを最初から想定し、後付けで正解行動の定義を変更しない。
  全候補を実測できない場合はregretをUNKNOWNにする。

25.1 CAPE/Agentic Visionテスト

38. 独創性を主張するための具体的な反事実実験

38.1 具体的な三つの驚きケース

  Case B: 結び直しだけでは改善せず、特定の層の再配置で改善する束。

  Case C: AIが追加プローブをしないほうが合理的な通常束。
    ・固定プローブ方式の追加時間と試験による状態変化を記録。
    ・CAPEのSTOPを行動価値の一部として評価。

  E-D差なし→『新しい能動知覚で従来法を超える』主張を撤回。

38.3 実験結果の提出様式

39. 統計の実行基準とデータ品質の監査
========================================================================================
39.1 試験群の独立性の単位
  基本はconfiguration_idとphysical_sample_id。1試料の繰り返し動画やデコード差は独立例ではない。
  主要比較E-D/E-Bは構成単位のpaired differencesを出す。
  全比較を行ったら多重比較/探索分析を分けて記載する。

39.2 小標本で言えること/言えないこと
  8構成の全勝であっても幅広い一般化を意味しない。個別効果・不確実性・悪化構成を併記。
  少ない試料で事前のδを超えても『有意な実用勝利』と即断しない。
  95%CIだけでなく独立試料数、失敗・中止・スケール外割合を表示。
  ブートストラップは構成単位。独立構成数が極端に少なければ参考程度とする。

39.3 選択的分類の実装仕様
  Coverage=N_non_unknown/N_all。
  SelectiveAccuracy=N_correct/N_non_unknown（N_non_unknown=0ならnull）。
  modeごとのRecallの分母はGT陽性全件とし、UNKNOWNは偽陰性として数える。
  Precisionは該当原因を確定した事例に対して計算し、該当確定0ならnull。
  全UNKNOWNのケースをcoverage=0で拒否して、精度の分母を『確定した正解だけ』にしない。
  合成の正答率を自然発生事象にそのまま外挿しない。

39.4 有効な共通チャレンジQ
  challenge_id、実測input_force_N、duration_s、amplitude_mm/frequency_hz（該当方式に限る）、
  fixture_revision、material_batch、mass、room condition、probe historyを照合。
  未取得物理量はNOT_MEASUREDとし同条件と推測しない。
  validate_challenge関数は「力と時間等の許容差」照合の一部だけであり、
  実物の全条件の一致や物理荷崩れの因果性までは保証しない。

39.5 中止・抜け落ち・破断の扱い
  完了率を全件分母で報告。中止された場合、T_jobは右打切り等の条件付き測定となる。
  単に完了者の中央値を比べる分析には選択バイアスがある可能性を明示。
  最悪シナリオに中止を含める感度分析と、失敗件数自体の比較が必要。

39.6 AIと人間の公平性
  人間Bは事前に訓練された標準方法に加え、結び直し/再配置/分割を自由に使う。
  CAPEだけ追加プローブを使うなら、その費用と状態変化も計上。
  同じ束でDを行った後にEを行わず、同仕様の別試料または交互割当を優先。

42. v4.1修正された4BLOCKERと厳格回帰テスト
========================================================================================
42.1 B-01 ひも経路滑りのみでKEEPする欠陥
  再現入力：quality=VALID, layer=0, rope=7mm, knot=0mm, threshold=5mm。
  旧出力 KEEP は誤り。修正版は REPOSITION_TWINE（地域規則・許可済み計画に限る）。
  knot=None の場合はPROBE_KNOTまたはABSTAIN。残プローブ0ならABSTAIN。
  層間滑りとひも滑りが同時に出ればMULTIPLE_FAULTS_REQUIRE_REVIEW → ABSTAIN。
  修正済コード：code/cape_rule_core.py。ローカル回帰：ROPE-001～004, RULE-029。
  『ひもが動いた』ことから結び直し必要性を自動断定しない。許可されない場合はABSTAIN。
42.2 B-02 未発行/未許可のactionを承認する欠陥
  承認に必要：session.owner_sub==auth_sub、session.state==PLAN_READY、expected_version一致、
  actionはPHYSICAL_ACTIONSかつsession.allowed_actions内、planned_action_idと一致、
  planned_observation_id一致、region_rules_verified、safety_preflight_ok、policy_version一致。
  単純なUI allowlistではなくAPI・DynamoDB側で強制。失敗はActionError;変更イベントを残さない。
  コードはローカルの不変条件の参考実装。実運用ではDynamoDB条件付き原子更新が必須。
42.3 B-03 idempotency-key同名異なる操作の受け入れ
  操作ID,session_id,owner_sub,expected_version,observation_id,policy_versionを正規化JSONのSHA256へ結合。
  同キー同bodyなら初回承認結果を返す、別bodyならCONFLICT。セッションが進んだ後の
  古いキーには現在の新セッションを旧成功結果として返してはならない。実運用では初回HTTP応答を
  原子的な冪等性テーブルに保存し、それを返却する。ローカル参照関数はその場合エラーで明示停止。
42.4 B-04 同じ規定外物理入力で比較しても合格する欠陥
  profile={'challenge_id':'Q','input_targets':{'input_force_N':{'target':pilot_F,'tolerance':pilot_eps},
            'duration_s':{'target':pilot_t,'tolerance':pilot_eps_t}}}。
  対照B/Eのそれぞれが規定目標内にある必要があり、その後、群間差も許容範囲内か検査。
  profile空/ターゲット欠落/非有限/両群とも規定外なら例外。Fの実数はこの文書では設定しない。
  静的荷重のピークだけでなく波形・負荷速度・持続も別途物理装置で監査（ローカル関数は未実装）。

43. 原因→行動の決定表・人間承認と状態不変条件
========================================================================================
原因入力                         推奨初期判断                     証拠・条件
Knot-only >= threshold            RE_TIE                          合法な既存方式のみ
Layer-only >= threshold           REORDER                         どの層が動いたかを可視化
Rope-only >= threshold, knot=0   REPOSITION_TWINE                許可外ならABSTAIN
Rope-only >= threshold, knot=None PROBE_KNOT                       試験回数上限ならABSTAIN
複数故障                            ABSTAIN                          単一行動で無理に改善しない
三項目0かつVALIDかつ全て観測        KEEP                             安全保証なし
いずれか不明か遮蔽                 RECAPTURE/PROBE/ABSTAIN          未観測=0禁止
全候補禁止                         ABSTAIN                          禁止行動の自動強行なし

STATE: PLAN_READY->APPROVED->OUTCOME_PENDING->(適切な観測で)PLAN_READY。
承認は人がUIで行い、ユーザーの実施確認なしに実物作業完了を偽装しない。
プローブ実施完了後でも、実観測がサーバ側登録済みであることを確認してからprobe_countを増やす。
研究モードでも回数上限の永続化、承認取消、再送、他ユーザーからの侵入、タイムアウトを試験。

44. 共通Qの規定入力一致・中断時の評価仕様
========================================================================================
最終Qの規定目標と許容差はパイロット終了後に凍結して署名。現物未試験のためF_maxは未定。
Qの入力チェックは(1)各群の目標達成(2)群間同等性(3)試料・治具・プロファイル・計測器の
一致(4)試験時刻と入力波形(5)中止・逸脱・再試行ログの5層。
code/evaluation_core.py のvalidate_challengeは(1)(2)(3)の基本フィールドを検査。
入力時間波形と荷重の連続データは別の実機サンプラー、校正とプロトコル審査で成立させる。
失敗・中止・搬出未完了は0秒や成功としない。summarize_all_attemptsは全試行の完了率と中止数を集計。
paired_effectは完了ペアのみの探索的な時間差で、ITTではない。全試行での統計的推論は別途行う。

47. M/Uトラックの実用価値と統計判定
========================================================================================
M-TRACK：E(能動) vs D(固定)。故障原因の正確さだけでなく、誤修正率・診断コスト・最終Q損失。
U-TRACK：E(支援) vs B(強い熟練者)。全枚数完了・準備を含む作業時間・崩れ・解けを独立表示。
両比較の方法・主指標・必要サンプル・差の方向は先に凍結。複数手法の事後的な選り好み禁止。
独立構成8種の初期データは探索的。試料再利用の効果を分離し、構成単位で対応差とCIを報告。
失敗した試験が片群のみ多い場合は完了者のみの時間中央値で『時短』を主張しない。
過去の一時的な『推奨行動と一つの正解一致』を完全なoracleとせず、
異なる行動が同程度の損失になる場合は許容行動集合を定義して複数解を認める。

### 51.1 行動の論理と単位の規定

`choose_rule_action()`に入力する`Observation.layer_slip_mm`は、校正されたmm値でなければならない。APIや実画像パイプラインは**原画像のpxを直接渡してはならない**。境界で校正ID、平面ID、参照座標、校正状態、推定誤差を検証する。

単一スケール変換は同一校正平面でのみ近似できる。層の奥行きや傾きの変化が分からない場合、`OUT_OF_PLANE_UNKNOWN`または`UNCALIBRATED`で判断保留。合成データの1px=1mmは研究用仮定であり、実物のGTではない。

不確実性を過小評価しない。閾値5mmに対して例として推定5.2±0.5mmのように境界をまたぐ場合、v4.2の研究パイプラインは推定値だけで修正を確定せず`UNCERTAIN_METRIC_BOUNDARY`によって再撮影/保留する。ただし独立GTによる95%区間としては未校正であり、倍数による範囲表示を統計的なCIと誤認させない。

ひも・結び目が未観測の場合には、0mmを代入しない。研究用CLIの`ROPE_AND_KNOT_NOT_MEASURED`は原理上の必須注記。自動層ID認識はCLIに実装していない（研究者が提供するupper/lower maskに依存）。

### 51.2 プローブの状態管理

- `PLAN_READY -> APPROVED -> OUTCOME_PENDING -> PLAN_READY` の間、計測の上限を同一セッションで保存。
- 診断プローブの計数上限は承認・実施・結果登録で一貫して検証。1つ承認した後に別プローブを承認することは状態機械が拒否。
- `probe_count`は完了数、`pending_probe_count`（AWSで実装が必要）は承認・実行中の予約数。AWSでは`completed+reserved<=max`の不変条件をトランザクション条件に入れる。
- 人間の承認と実施完了を同一のイベントとして扱わない。結果動画と一致する観測IDが無ければ物理試験完了を確定しない。
- 操作の許可は自治体規則・撮影品質・人の安全確認を通過した場合に限る。反復試験が物理的に安全とは宣言しない。

## 52. 意思決定を「発見的ルール」から検証可能な能動試験へ

### 52.1 CAPE-4.2のコード範囲

1. **実装済（ローカル）**：閾値＋禁止行動＋上限＋人間承認の`choose_rule_action`。
2. **新規実装（ローカル数学のみ）**：`toy_cape_voi.py`は有限状態の既知モデルについて、試験による`M_current→M_next`と観測`y`の同時確率から期待損失を計算。不正確率・未正規化確率の検証、No Probe、試験コストを扱う。
3. **未実装**：実画像／実験により校正された`P(M_next,y|M_current,a)`。これが無い状態で`EVSI実運用最適化済`と称してはいけない。
4. **未実証**：EがDより少ない試験コストまたは小さな修正後の実損失を達成すること。

計算式：初期状態分布`b(m)`、最終修正`u`、プローブ`a`、次状態`m'`、観測`y`、実行費用`C(a)`。

- `R_no_probe = min_u Σ_m b(m)L(u,m)`
- `R_probe(a) = C(a) + Σ_y min_u Σ_m' P(m',y|b,a)L(u,m')`
- `a*=argmin({R_no_probe}∪{R_probe(a):a∈A_safe})`。

これは有限サンプルの模擬モデルに対して実装。実物の遷移モデルを与える前にアプリが危険な物理試験を自動承認することは禁止する。`NO_PROBE`は正当な最適解。

### 52.2 複数の正しい修正とRegret

同じ束で異なる修正を同時に実行できないため、1ラベルの「唯一正解」に過度に依存しない。事前登録した同等性幅ε以内の損失を生む手順を許容修正集合とする。修正後Qでの実測結果と、別試料を使った対照実験に基づいてのみRegretを推定する。未検証の反事実を`measured`として表示してはならない。

### 52.3 固定試験対照が弱くならない条件

- **D**：初回観測後に事前指定の固定プローブを実施し、その結果に基づいて再計画する。
- **E**：初回観測ごとに可視データが意思決定を変えるプローブ/不介入を選び、その結果に基づいて再計画する。
- 試行回数上限、材料、最大荷重、診断時間、最終チャレンジQを同条件に設定。必要なら試験負荷の対照群を別に設ける。
- 失敗例と不介入のケースを双方に含める。Eだけに人間の追加情報を与えない。

### 54.1 先に可観測性を確認

### 54.2 Primaryと欠測処理

M-TRACKはE-Dの「最終修正損失または誤修正率」を**ひとつ**主要指標に選んで事前固定する。U-TRACKはE-Bの「全枚数完了率または完了を含む全作業損失」を主要指標に選んで固定。副指標の作業時間は成功・失敗を区別して扱う。

8独立構成は探索的な最小確認にすぎない。確認的なn、最小意味差、CI幅、力不足の危険をパイロットの分散・事前感度解析から算出する。同じ束の再撮影を独立データとして数えない。層間滑りは全体運動キャンセル後のベクトル・相対角・局所変形を別表示。

- 完了した試行のみの時間平均はITTではない。完了率と失敗時の計数を必ず併記。
- `ABORTED/FAILED/INCOMPLETE`をゼロ秒、ゼロ滑り、成功として代入しない。
- 2つのPrimary比較で複数推論をする場合は、多重性を事前に設計し、P値が無くても効果量と不確実性を示す。
- 未知環境への一般化、運搬時の安全強度、50年需要を小標本から断定しない。
