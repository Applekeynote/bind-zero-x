# BIND ZERO-X v4.5 — 証拠付き介入制御・多段階能動知覚の正式改訂仕様

版：v4.5 / 2026-10-12 JST。基準資料：ユーザー添付v4.4 ZIP。**本書がv4.2〜v4.4と矛盾する場合は本書を優先する**。ただし既存機能の全詳細は旧版仕様を参照する。

## 0. 狙い、95点超との関係

目的は「段ボールをうまく結ぶ方法をAIに説明させる」ことではない。**どの故障が区別不能なのか、どの追加視点なら修正判断を変える可能性があり、何も見る必要がない条件は何か**を、失敗時に保留できる証拠付きの意思決定として実装する。

これは**95点超を獲得済み／獲得確実という意味ではない**。ローカル純粋関数・合成画像の品質向上だけではTechnical/Innovation/Impactの上限を主張できない。現時点で実物の層間変位、ひも・結び目、Azureではなく**AWS**上のOpenCV 5、ベテラン対照、無作為化試験の成果は一切未実証。

公式審査の100点配分はTechnical 30、Innovation 20、Real-world Impact 20、UX 10、Documentation 10、Cloud/Reproducibility/Responsibility 10。公式：https://opencv26.devpost.com/rules

## 1. v4.4監査の3欠陥をコードから修正

### R45-01 証明の意味的検査：ハッシュは数学的証明でない

`witness_planner.verify_witness_certificate`は、従来SHA256と公開フィールドの一致しか見なかった。v4.5では証明書の**元の可能世界、損失表、予想視点結果、費用、予算、モデル版**を復元し、`recommend_witness`を新しく実行する。全ての派生結果（最適行動集合、最小衝突核、最大後悔量、採択視点、候補視点の残余損失、結果判定）が再計算結果と完全一致しない証明書を失効させる。**さらに計画器をimportしない `independent_witness_checker.py` の有限列挙でも独立照合する**。ただし入力モデル自体の真実性を証明しない。

判定：`SHA256(p)==hash` **だけではFAIL**。さらに `Planner(inputs(p)) == published_decision(p)` を要求。`v44_adversarial_reproduction.py`の偽書類を改変後に再ハッシュしてもVERIFY=Falseとなることを確認する。

ただし**自己整合性と認証は異なる**。攻撃者が損失表・モデルと証明書を丸ごと別物に変える可能性に備え、校正済み扱いにする場合は**サーバ側で事前凍結したmodel_fingerprint、画像SHA、校正ID**との照合が必須。クライアントやLLMが`model_calibrated=True`と送っただけでは採用しない。これらが合っても物理操作は承認せず、人間承認待ち候補止まり。

### R45-02 Optical Flow失敗の確実な扱い

順方向/逆方向の配列、ステータス、点数、次元、非有限値を確認。戻り値Noneの場合`BACKWARD_FLOW_FAILED`、形状不正`FLOW_SHAPE_INVALID`、非有限`NONFINITE_FLOW`。OpenCV例外は`FLOW_OPENCV_ERROR`または`AFFINE_OPENCV_ERROR`として機械判別できる失敗に変換。**測定不能を0mmに置き換えない**。

### R45-03 最悪後悔量だけで危険な直接判断を認めない

仮定モデル内部のミニマックス後悔量 `R_regret=min_u max_w[L(u,w)-min_v L(v,w)]` は、全候補が酷い結果を生む場合でもゼロとなり得る。これを避けるため `max_w L(u,w) ≤ L_abs_ceiling` という**別軸の絶対損失ゲート**を追加。初期値10は旧版モデルの**無次元の例示損失用**であり、物理的な安全閾値・許容荷重の根拠ではない。研究用途では事前登録・独立GT後に再設定する。違反時はABSTAIN。物理の許認可とは独立である。

## 2. 新規性を実行可能な差分として定義する

名称：**Proof-Carrying Intervention Gate（PCIG）**：証拠に基づく行動制約を持つ非接触能動知覚。

PCIGは次の4要素の統合を狭義の提案とする。

1. **Failure Interaction Graph**：LAYER_CONTACT/ROPE_PATH/KNOT_ENDを独立の観測チャネルとして明示。未観測値は0にしない。現段階では型付き*証拠グラフ*であり、物理的な因果グラフの学習ではない。
2. **Minimal Conflict Core**：可能世界の全体で共通最適行動があるかを計算し、なければ最小の衝突世界集合を示す。単なる2世界タイブレークを反例と偽らない。
3. **Pessimistic Next-View Value**：観測予想が不明・遮蔽なら「見れば必ず分かる」と仮定しない。固定視点との比較を同一枚数・同一時間予算で行う。追加の物理荷重を与える診断は実証前に一般利用へ提案しない。
4. **Semantic + Provenance Gate**：意思決定を独立再計算して検証し、画像・校正・モデル版をサーバが保持した証拠に拘束。絶対損失・承認・不確実性の境界をそれぞれ確認する。

**新規性の境界**：能動知覚、ミニマックス後悔量、形式的検証、撮影誘導は既知概念。既存の検査/証拠主体のAgentic Vision作品とも機能重複の可能性がある。『世界初』『競合なし』『理論を発明』とは主張しない。競合との差を実証するには、明示的なアブレーションが必要。

## 3. v4.5 多段階状態遷移

`active_evidence_loop.py`は `start_research_loop`→`continue_research_loop` の有限状態ループ。次に選ばれたビュー以外を受理せず、視点予算、画像SHAの再利用、予期しない観測、モデル不整合を拒否する。

1. 初回OpenCV画像計測は `research_pipeline.analyze` が担当。ROI帰属はオペレータ確認が必須。OpenCV 5での本稼働は未確認。
2. 仮定モデルに基づくPCIGが必要ならビューを提案。撮影者は非接触で撮り直す。一般利用者に物理的な引張を命令しない。
3. **v4.5のAPIから受理できる追加視点の原因ラベルはHUMAN_REPORTEDのみ**。これをOpenCVによるひも/結び目計測と呼ばない。
4. `CV_LAYER_ONLY`による自動更新には、実画像・バージョン・校正証拠を独立照合する**サーバ内検証関数**が必要。研究ローカルのモックテストの成功を実証扱いにしない。
5. 追加観測後の可能世界を絞り、損失表・候補視点を残存世界に再構成し、証明書を**新たに計算**する。`trace_dict`が前後の世界集合と証明ハッシュを記録。
6. セッションの任意時点で`approval_authorized=False`。物理介入は別途の認可・実ユーザーの意思確認・地域法令確認を要する。

### API（研究専用）

- `POST /api/research/analyze`：認証された2フレーム＋手動確認ROIのOpenCV 5ワーカー。**OpenCV 4では拒否**。
- `POST /api/research/loop/start`：有限仮説モデルに対して最初の非接触視点を選ぶ。現状はモデルを呼び出し元が入力できるため、完全な物理真実やサーバ側のモデル登録と混同しない。
- `POST /api/research/loop/reobserve`：上で指定した視点からの**人手の観測申告**で再計画。ローカルSQLiteに研究ログを保存し、`expected_version`による排他更新。
- `GET /ready`：OpenCV 5とトークン設定を検査（実AWSでの成功は未実証）。

研究APIは単一トークン・単一オペレータ用。AWSのCognito、DynamoDB、マルチテナントIAMやBedrockは**未接続**。物理操作を許可するAPIは存在しない。

## 4. 反証可能な「独創性」の評価（結果は未取得）

| Arm | 説明 | 分離したい効果 |
|---|---|---|
| A | 通常の適切な十字結束 | 既存の標準法 |
| B | 熟練者の自由な並べ替え・分割・結束 | 強い人間対照 |
| C | 初回画像のみ、追加視点なし | 画像認識の効果 |
| D | 固定された追加撮影1回 | 単純な追加情報 |
| E1 | 観測候補の一般的なルール選択 | 適応性の効果 |
| E2 | BIND-WITNESS/PCIG（最小衝突核+証明+保守的視点） | 本提案固有の上積み |
| E3 | E2から証明ゲートを除くアブレーション | 証明ゲートの実用価値 |

- M-TRACK主要比較：**E2対Dの全試行分母の誤介入率**。不正確な修正、不要な修正、断定不能時の誤介入を事前ルールでラベル。`ABSTAIN`を正答へ水増しせず、coverage・有効操作率を併記。Dの固定視点はholdoutを見る前に凍結。
- M-TRACK副比較：E2対E1/E3の誤介入率、撮影回数、時間、実際の原因識別。実験前の利益仮説：誤介入率を絶対10ポイント以上減らす。これは**目標**であり測定値ではない。
- U-TRACK主要比較：**E2対Bの全束搬出仕事の完了率**。成功者に限定した所要時間・往復数を別々に報告。分割後は元の全枚数を評価。重要な故障が発生した仕事は完成扱いにしない。
- U-TRACK副比較：残留層間滑りD_res、結び目端K_res、総T_job、ロープ経路滑り、撮影の負担、試験中断。一般向けの研究治具なし運用で取得した成績を別に示す。
- 中心仮説の反証条件：E2が固定視点Dより誤介入を減らさない、撮影負担で便益を相殺する、熟練者Bより改善しない、GTで故障を区別できない場合は、当該新規性/実用性の優位性を撤回する。

## 5. 実物・AWSの品質ゲート（すべて未実施）

- **G0**：ローカル数理・証明意味検証・例外処理・API境界テスト。実行ログとケースIDが対応すること。
- **G1**：OpenCV 5をAWS EC2またはAWSの適切な実行環境で**実際に**読み込み、ROIと2フレームから実測出力を返す。実ランタイム版、Docker digest、EC2 instance ID、CloudWatch request IDなどの機械的証拠。
- **G2**：独立GTによる層運動のMAE/P95/被覆率。共通回転による偽陽性0などの挑戦目標を、事前凍結。画像のみでは見えないひも裏側・結び目はUNKNOWN。
- **G3**：PCIG→非接触追加撮影→OpenCV再計測（SIDE/TOPなど対応チャネルのみ）→世界集合→再計画→人の確認。**現APIはひもの観測を人が報告しているだけ**なので、OpenCV 5実映像に基づく複数回の行動変化は追加実装必須。
- **G4**：E2対Dの比較。独立構成でランダム化し、撮影予算一致、失敗/中止を除外せず、クラスタ単位95%区間を公開。小標本なら探索的結果と明示。
- **G5**：E2対Bの比較。完成仕事の定義が同じ、全材料を含む。時間・結び目・運搬の3要件を別々に報告。
- **G6**：Web操作、実AWSエンドポイント、第三者再現、負の例、応募動画5分以内。Bedrockは未使用なら使用したと宣伝しない。

**95点超を主張する条件**：G1〜G6の実行成功、独創性の先行技術との厳密な差分証拠、実使用の便益の頑健性、セキュリティとUXの第三者検証が必要。目標配点29/30 +19/20 +19/20 +9/10 +10/10 +10/10 =96 は結果の保証ではなく、要件を満たした場合のチャレンジ目標。

## 7. 説明責任

- `verify_witness_certificate`は**入力された有限モデルの数学的自己整合性**のみ検証し、物理的な真実、モデル由来、信頼性や安全を保証しない。
- `HUMAN_REPORTED`の追加観測は**人の申告**でありOpenCV視覚解析の結果と呼ばない。
- `SQLiteResearchLoops`は開発用の排他的状態保存。分散AWSでのセッション管理を実装済みと称さない。
- ローカルOpenCV4の検証を必須のOpenCV5使用と混同しない。
- 観測不能/不確実性不明時は安全な修正であると判断しない。一般家庭での運搬安全性や耐荷重保証を絶対に表示しない。
