## 2. PCIG v4.7：技術的な独創性をどこに置くか

**独創性を主張する最小単位**は「最小衝突世界集合（どの故障の組み合わせを見分ける必要があるか）」と「非接触の次の視点選択」と「証拠不足時に物理介入を止める意味的に検証可能な判断証明書」を、層・紐経路・結び目の異種故障に一体化させることである。能動知覚・最小最大後悔量・光学フロー・ハッシュはそれぞれ既知であるため**個別手法の発明とは主張しない**。

**新しい検証可能な特徴:** 追加視点を選ぶ場合、後悔量の低減だけでなく、「どの観測結果であっても許容絶対損失以内の**非ABSTAIN**な候補が存在するか」を別に試験する。これにより、絶対損失が大きいのに後悔量が許容内という理由だけで有効な追加観測を捨てる以前の不具合を減らす。ただし観測値を保証できない実物ケースでは保守的にABSTAINする。

意思決定式（**仮説モデル内部の定義**）：

- 可能世界集合 `W`、合法行動集合 `A`、損失 `L(a,w)`、非接触視点 `v`、予想観測集合 `O(v,w)`。
- 後悔量 `R(W) = min_a max_{w∈W}[L(a,w)-min_b L(b,w)]`。
- 視点コスト込み最悪後悔量 `C(v) + max_{o} R({w∈W | o∈O(v,w)})`。
- **絶対損失制約**：`∀o, ∃a≠ABSTAIN : max_{w:o∈O(v,w)} L(a,w) ≤ Lmax`。
- 絶対損失制約は決定を許可する十分条件ではない。実測誤差の妥当性、認可状態、人間承認が別途必要。

### 比較するアブレーション

1. `D0`：固定TOPのみ。
2. `D1`：固定TOP＋SIDEを常に取得（「単に撮影枚数が多い」効果を分離）。
3. `E1`：未観測項目を機械的に選ぶ単純適応。
4. `E2`：PCIG全機構（衝突集合、保守的予測、絶対損失、証拠ゲート）。
5. `E2-ablated`：PCIGの衝突証明・介入ゲートを一つずつ無効化。失敗率と撮影回数を比べる。
6. `B`：経験者が視点、結束、分割、全枚数搬出を独立に選ぶ。E2と比較する際には人間にも同じ開始状況と作業自由度を与える。

**独立した主評価**：E2 vs D1 の誤介入率差（E2が正しい、またはより少ない誤介入）。副評価は総時間・追加撮影数・ABSTAIN率・失敗率。第二軌道ではE2 vs Bの全作業完了率と総時間、元の枚数 `N` を**一切除外せず**評価する。データ取得開始前に主要評価一つ・検定・必要標本数を外部記録へ凍結。

## 3. 視覚→証拠→判断の結合仕様

### 3.1 純粋な画像処理

OpenCVによる2フレーム相対SE(2)推定：専門家ROIの帰属確認、前後LK光学フロー、RANSAC、異常尺度棄却、可視上層ROI内の凸包頂点上で最大移動量を算出。測定成功でもROIの物理的同一性、被遮蔽層全体の変位、保持荷重を証明しない。**異なる奥行きで単一のmm/px換算を使わない。**

### 3.2 校正とGTエンベロープ

- 入力の `PlaneCalibration.verified` および `.frozen` は**本物のbool**のみ受理（文字列や1/0は拒否）。これは**要求本文の型**の確認であり、これ自体が独立GTの承認ではない。
- `BZX_APPROVED_GT_ENVELOPE_PATH` と `BZX_APPROVED_GT_ENVELOPE_SHA256` がサーバで固定され、JSONとその独立GTの審査記録が整合した場合だけ研究用の証拠ゲートへ進める。環境変数はHTTPで受け付けない。
- 閾値前後の `±P95誤差` を考慮し、確定域なら `layer_moves`/`layer_still`、重なれば `?` とする。**P95は最悪ケース保証でも機械安全保証でもない**。独立GTの正当性は人間の審査・原動画とセットで検証する。
- 未承認・形状/校正不一致・記録改変・閾値近傍の場合、可能世界集合を縮約しない。
- `experiments/prepare_gt_envelope.py` が作るのは**未承認DRAFT**であり、`approved=false`などは既定で変更されない。独立者の確認、外部の凍結証跡が成立するまでは稼働環境で使用禁止。

### 3.3 観測の親子関係

`session_id`, `observation_id`（親）, `O:view1`（追加画像の子）, `view`, `state_version`, `capture_sha256`, `roi_manifest`, `calibration_id`, `certificate_hash`を監査ログで参照する。別親ID、古い版、違う視点は画像デコード前に拒否。EvidenceStepは親と子を保存し、履歴再生時にも照合する。既存の研究用単一トークン認証を本番の利用者認証とみなさない。

### 3.4 観測が本当に次の行動を変えるか

- 仮想GTレジストリをテスト環境でモックした**合成**検査では、同じモデルで静止画像が世界B、移動画像が世界Aを選ぶことを回帰テストする。
- 本番では独立GTで妥当性を確認したレジストリがまだ無いため、実画像の0mmと7mmの違いだけで故障を断定しない。これを製品完成と呼ばない。
- 追加画像から紐経路・結び目の数値を取得するセグメンテーション実装は**未実装**。観測の範囲は層間の可視2D運動に限定。紐・結び目の既知GTがない場合は、現行の保留条件を維持する。

## 4. 実物評価プロトコル（実行前の案）

1. 事前に3種以上の段ボール寸法・厚み構成、2種以上の故障モード、撮影距離・角度・光条件を固定する。結束方法と安全上限を監督者と定める。負荷を伴う危険な試験は専門機関の治具で行い、ひもや荷を身体・動物・通行路へ向けない。
2. GTは映像推定とは独立に、層端マーカ座標の定規計測・別カメラ校正・独立計測者によって取得。CV測定をGTに流用しない。必要なら2人の読み取り一致を測る。
3. PILOTのみで閾値とモデルを選定し、その後に評価ルール・除外条件・最小改善差・統計手法を事前登録して凍結する。HOLDOUTの情報を閾値決定に使わない。
4. 少なくとも30の独立物理試行を使うことを**スクリプト上の最低入力要件**とする。ただし30件は統計学上の十分な検出力を保証しない。独立性の単位はフレームではなく、束・物理試行。フレームの大量水増しは禁止。
5. `experiments/holdout_gt_record_template.csv`に、試行ID・束ID・モード・独立GT・CV値・担当者・原動画ハッシュを記録。`prepare_gt_envelope.py`でP95/MAEを出力し、第三者が動画とCSVを監査してから承認。
6. 各方式で修正結果（層、紐、結び目）を再計測。全枚数の運搬/束ね直しの時間・中止・事故・撮影時間・人間の介入を欠損なく記録する。
7. 難しいケースでE2がABSTAINを増やして誤修正を減らす場合、誤修正とABSTAINの両方を報告し、都合の良い条件付き正答率だけを報告しない。
8. `analyze_physical_comparison.py`は対照ペア単位の差を計算し、無記録ならエラーで停止する。出力は記述統計であり、無作為化・盲検・除外理由の検証を行うまで優越性の因果的証拠ではない。

## 5. AWS/OpenCV5の提出必須ゲート

公式概要は「OpenCV 5の実質的な画像・動画解析」と「AWSで意味ある構成要素の稼働」を要求する。Dockerfileに5.0.0.93のPyPIパッケージを指定済みだが、Dockerfileの**存在は実行証拠ではない**。

1. EC2で `docker build --pull -f deploy/Dockerfile -t bind-zero-x:v4.7 .` を実行。**失敗時は未達**。
2. `docker run --rm --entrypoint python bind-zero-x:v4.7 -c 'import cv2; print(cv2.__version__,cv2.getBuildInformation())'` の標準出力、イメージdigestを記録。
3. 研究用サーバの `/ready` に実リクエストを送りOpenCV5の起動を確認し、静止と滑りの実画像についてGTに対する誤差ログを保存。
4. E2多段階セッションをEC2上で `start→reobserve-image→witness→next view/abstain` と実行し、S3へ匿名化した画像・ログ、DynamoDB等へ状態バージョン・利用者認証・冪等性を保存。**現在のZIPはEC2ローカルSQLiteまで。**
5. Bedrockの利用は必須ではない。使用する場合もPCIGの行動許可をLLM単独に委ねず、ツール入力のスキーマ検証・人間承認・権限分離を守る。
6. EC2は外部直接公開しない。TLS、最小IAM、KMS/Secrets Manager、CloudWatch、料金制限、アクセス監査を整える。画像やGTの公開には権利確認。
7. 必要な提出物：実演動画（5分以内）、再現手順、公式ルール確認、OpenCV5/AWSの一次実行証跡、失敗例、限界、比較結果。
