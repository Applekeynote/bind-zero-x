# v4.4 AWS/OpenCV 5 実稼働・デプロイ手順（未実施）

研究用FastAPI実装：`code/api_research.py`。配布Dockerfileは **常駐サーバ起動**に変更。GitコミットとDocker Digestを証拠に保存する。`BZX_RESEARCH_TOKEN`は32文字以上でAWS Secrets Manager等の安全な手段から注入し、ログに記録しない。公開通信はHTTPSリバースプロキシ経由とし、研究用APIを認証無しでインターネットへ公開しない。

## 1. コンテナ

```bash
docker build --pull -f deploy/Dockerfile -t bind-zero-x-v44:runtime .
docker run --rm --network none bind-zero-x-v44:runtime python -c 'import cv2;assert cv2.__version__.split(".")[0]=="5";print(cv2.__version__)'
docker run --rm --network none bind-zero-x-v44:runtime python -m unittest discover -s code -p 'test_*.py' -q
```

実API起動は既定CMDで`uvicorn api_research:app --host 0.0.0.0 --port 8080 --no-proxy-headers`。ただし本資料のコマンドを実行した証拠はまだない。実際のネットワークはAWSプライベートサブネットと認証リバースプロキシの背後でのみ許す。

## 2. リクエスト契約

- `GET /health`：バージョン情報（検証済みを表すものではない）。
- `GET /ready`：OpenCV5稼働・認証トークン設定済みのときのみ200。それ以外503。
- `POST /api/research/analyze`：`Authorization: Bearer <BZX_RESEARCH_TOKEN>`、frame0/frame1/upper-mask/lower-maskのPNG base64、2層ROIの元画像SHA256・マスクSHA256・source_idを含むmanifest、校正ID・平面ID・mm/px、観測ID。戻り値には測定、FIGハッシュ、CWC、単一ゲートの保留判断を含む。画像は永続化しない。単体APIは人間承認やDynamoDBによる本番履歴処理を代替しない。

## 3. 実AWSエビデンスに必要なもの

1. EC2リージョン/プライベートVPC/インスタンス名の匿名化、Docker Image Digest、OpenCV5ランタイムログ。
2. 実物の2フレームとROI ManifestのSHA256、GTからの誤差、検査員による層ID帰属。
3. S3の非公開オブジェクト（アクセス制御・期限・削除検証）とリクエストIDを紐付ける。
4. DynamoDBでowner照合、状態版の条件付き更新、承認・実行確認分離、永続冪等性を実装する（**未実装**）。
5. Webの2段階観測→追加視点→再撮影→WITNESS再計画→本人確認→最終Qのトレース。**現Research APIは2段階を永続化しない**。
6. CloudWatchに個人情報や生画像を残さず、CloudTrail/IAMで最小権限とアクセス監査を検証。
7. Bedrockを使うなら意味的に正しいallowlistとfallbackを検査。Bedrock未接続の間はクラウドAgentic機能の証拠としない。
8. 機能が動いた時刻と計測結果を原本として署名/ハッシュ化し、審査員が再実行可能なコマンドを掲載。

## 4. Gate

`AWS_OPENCV5_REAL=NOT_RUN`、`AWS_S3_DYNAMODB_E2E=NOT_RUN`、`REAL_GT_NOT_RUN`、`REAL_ACTIVE_VIEW_BENCHMARK=NOT_RUN`。これらの状態はローカルの233件PASSがあっても自動的に変わらない。

公式ルール：https://opencv26.devpost.com/rules。必要な提出物は5分以内の動画、コード/デモへの審査員アクセス、実測根拠と再現手順。
